# 역할
당신은 음성합성(TTS)·음성복제 분야의 시니어 리서처이자, 한국어 낭독 콘텐츠를 자동 생산하는 오디오 엔지니어입니다.

# 배경 (내가 만드는 것)
- 프로젝트: 매일 '말씀 묵상 예배'(약 17분)와 '심방 말씀'(약 8분, 작은 방 소모임 설교)을 내 목소리 복제 TTS로 자동 제작하는 파이썬 파이프라인
- 환경: Mac mini M4(16GB 통합메모리, Apple GPU = PyTorch MPS), macOS 26, Python 3.12, torch 2.6, ffmpeg 8. 무료·로컬 실행이 원칙
- 현재 엔진: Chatterbox Multilingual 0.1.7(resemble-ai), 한국어 참조 녹음 약 15초 1개로 음성복제
- 현재 규칙: 한 문장씩 생성 → 문장부호별 쉼(마침표 0.7초·물음표 1.1초·쉼표 0.45초) 삽입, 엔진이 남긴 앞뒤 무음 다듬기, 12자 미만 짧은 문장은 다음 문장과 합침, 60자 넘는 문장은 쉼표 또는 절 끝(…고/…며/…서)에서 분할, exaggeration 0.25·cfg_weight 0.4, 완성 후 ffmpeg atempo 0.92로 8% 감속, faster-whisper로 되읽어 오류율 12% 넘으면 재생성(최대 3회), 급격한 샘플 튐('칙' 소리) 검사 + ffmpeg adeclick, 발음사전(영문 고유명사·약어를 한글 발음으로), 성경 장·절은 한자어 수로 풀어 읽기
- 남은 문제: ①문장마다 억양이 새로 시작되는 느낌·기계적인 쉼 ②긴 문장에서 갑자기 빨라짐 ③가끔 띄어쓰기·어절 경계가 어색 ④MPS 메모리가 생성 중 14~33GB까지 커짐(empty_cache·참조 분석 1회로 줄였으나 여전) ⑤참조 녹음을 EQ로 고음 보정하자 '칙' 잡음 증가
- 이미 아는 것: Gemini TTS는 자연스럽지만 유료·내 목소리 아님. Microsoft edge-tts(InJoonNeural)는 무료지만 내 목소리 아님(별도 영상에서 길이별 감속·절 경계 쉼표 규칙으로 튜닝해 사용 중)

# 조사 목적
무료·로컬(맥 M4) 범위에서 '내 목소리' 낭독을 가장 자연스럽게 만드는 엔진·설정·규칙을 정하고, 다른 사람 목소리를 빠르게 적용하는 표준 절차 문서를 만든다.

# 핵심 질문
1. 2026년 현재 무료(오픈 가중치) 한국어 지원 음성복제 TTS를 비교: CosyVoice 2/3, F5-TTS(한국어 파인튜닝판 포함), Fish Speech/OpenAudio S1-mini, IndexTTS2, Higgs Audio v2, GPT-SoVITS v4, Chatterbox(최신판·커뮤니티 개선판), 그 밖 신규. 기준: 한국어 자연스러움(운율·띄어쓰기), 제로샷 복제 품질, 긴 문단 안정성, 라이선스(상업·유튜브 수익 가능 여부), Apple Silicon MPS 실행 가능성·속도·메모리. 표로.
2. Chatterbox에서 자연스러움을 높이는 실전 설정: 문맥을 이어 생성하는 방법(이전 문장 조건·여러 문장 묶음의 적정 길이), cfg_weight·exaggeration·temperature·min_p 등 권장값, 긴 입력에서 빨라지는 원인과 대책, 한국어 토크나이저 특성.
3. 참조 녹음의 모범 사례: 길이(초), 문장 수·내용(설교체/대화체), 말 빠르기·쉼, 녹음 환경(마이크 거리·잔향·잡음), 후처리(EQ·노이즈 제거·잔향 제거)가 복제 품질과 잡음에 주는 영향. EQ 보정이 잡음을 늘리는 이유.
4. 한국어 TTS 텍스트 정규화 모범 사례: 숫자(한자어/고유어 구분), 영문 약어·고유명사, 기호, 성경 장·절, 날짜·시간. 공개된 규칙집·라이브러리(예: g2pk 등)와 적용 순서.
5. 문장 분할과 쉼(운율) 규칙: 한국어 낭독에서 문장부호·절 경계별 자연스러운 쉼 길이(ms) 연구·실무 값, 설교·라디오 낭독 속도(음절/초), 고정 쉼 대신 변동 쉼을 주는 방법.
6. 음성변환(Seed-VC, OpenVoice v2, RVC 등)으로 '자연스러운 무료 TTS(예: edge-tts)의 억양 + 내 음색'을 결합하는 방식의 품질·속도·라이선스·MPS 실행성. 직접 복제 TTS 대비 장단점.
7. PyTorch MPS에서 TTS 반복 생성 시 메모리가 계속 커지는 원인(캐시·그래프·가변 길이 텐서)과 검증된 해결책(환경변수·코드 패턴), 현재 버전 기준 변경 이력 포함.
8. 새 사람 목소리를 빠르게 적용하는 표준 절차: 녹음 대본 예시, 필요한 길이, 녹음 체크리스트, 자동 검수 지표(되읽기 오류율·잡음·화자 유사도), 흔한 실패와 해결.

# 범위·조건
- 기준 시점: 2026-10 현재. 2025년 이후 자료 우선, 오래된 정보는 연도 표기
- 언어: 한국어 낭독 품질이 핵심(영어는 참고)
- 제외: 유료 API·클라우드 전용 서비스(비교용 언급만), 실시간 스트리밍 TTS
- 출처 우선순위: 공식 저장소·논문·모델 카드 > 기술 블로그 > 커뮤니티(이슈·포럼). 영어·중국어 원문 적극 검색

# 출력 형식
- 한국어, 마크다운. 맨 앞에 "핵심 결론 5줄"
- 질문별 섹션 + 비교는 표로, 권장 설정값은 구체 숫자로
- 모든 사실 주장에 출처(제목·URL·발행일) 인라인 표기
- 각 결론에 확신도(높음/중간/낮음)와 이유
- 출처끼리 상충하면 양쪽 제시, 확인 불가한 것은 "확인 불가"로 명시
- 마지막에 "내 프로젝트에 바로 적용할 체크리스트"와 "추가로 조사할 질문 3개"
