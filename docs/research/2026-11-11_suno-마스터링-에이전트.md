# Suno 곡 자동 마스터링 에이전트 — 규격·도구·선별

## 핵심 결론 5줄
1. **목표값은 -14 LUFS 안팎, True Peak -1 dBTP 이하(-14보다 크게 만들면 -2 dBTP 이하), 16bit/44.1kHz 스테레오 WAV(또는 FLAC).** Spotify 공식 문서로 확인 ✅. 멜론·지니·FLO·VIBE의 음량 평준화 여부·목표값은 공개 근거 없음 ❓ → 국제 기준에 맞추면 된다. (높음)
2. **내 Suno 곡 실측(MP3 6곡, 2026-11-11)은 이미 "얌전하다"**: 48kHz, -13~-16.6 LUFS, 피크 -0.8~-4 dBTP, 고역은 약 19kHz부터 끊김(MP3 인코딩 흔적). 웹 벤더 글의 "Suno는 -8~-12 LUFS로 과압축·16kHz 컷"은 내 파일엔 해당 안 됨. → **세게 누르는 마스터링이 아니라, 고역 거칠기 정리 + 44.1kHz 변환 + 음량·피크 맞춤 + 검증**이 핵심. (높음 — 직접 측정)
3. **도구는 오픈소스로 충분**: 기존 karaoke-master `master.py`(numpy/scipy EQ·컴프·pyloudnorm) + **Matchering 2.0**(레퍼런스 매칭, GPL-3.0, 16/24bit 출력 ✅) + **4배 오버샘플링 True Peak 검증 루프**. pedalboard는 Mac(Apple Silicon)·Linux 휠이 공식 제공돼 맥미니에선 재시도 가치 있음. 상용 API(LANDR·RoEx Tonn)는 견적제라 개인용 부적합. (중간)
4. **"좋은 곡" 선별은 자동 1차 거름 + 사람 최종 청취**: 기술 지표(클리핑·True Peak·LUFS·LRA·무음·길이·위상)로 탈락시키고, Meta Audiobox Aesthetics·SongEval 점수는 순위 참고만. 독립 리뷰에서 미적 점수 모델 신뢰도가 낮다 ❓. (중간)
5. **원본은 가능한 최고 품질(유료 플랜 WAV)로, 업샘플·고역 복원(AudioSR·Apollo)은 기본값에서 뺀다.** 유통사가 손실 변환을 자동 탐지·반려한다는 공개 근거는 없지만 ❓, 끊긴 고역을 AI로 만들어내면 환각 위험. 24bit로 부풀리지 말고 16bit/44.1kHz(디더 1회)로 납품. (중간)

## Q5. Suno 결함과 사전 처리
- 공통 보고: 고역 쉬머·금속성 잡음, 보컬 3~6kHz 거침, 저역 뭉침(킥·베이스 겹침), 스테레오 배치 불균일, 리버브 과다(제거 곤란). (커뮤니티·벤더 글, 중간)
- v5 vs v5.5 깨끗함은 보고가 엇갈림(MasterForge 2026-03 vs 사용자 다수).
- 권고 처리: 리미터 **앞에서** 6~8kHz 이상 하이셸프 -1~-3dB 또는 디에서, 저역 120Hz 이하 모노화, 과도한 리미팅 금지. 이미 거친 고역을 올리지 말 것.
- Suno 스템: 최대 12개 WAV(Suno 블로그), 곡당 크레딧 소모·플랜 조건 상충 ❓. 제3자는 스템도 번짐·위상 문제가 있다고 지적 → **무인 파이프라인은 풀믹스 마스터링이 기본**, 스템은 "정말 좋은 곡" 수작업용.
- 외부 분리: BS-Roformer > MelBand-Roformer > htdemucs(MVSEP 보컬 SDR 12 / 11 / 8.3). 다시 섞으면 분리 번짐 추가 위험.
- 출처: https://www.roexaudio.com/blog/suno-stems-sound-bad-here-is-why-and-how-to-fix-them · https://masterforge-app.pages.dev/blog/suno-v5-vs-v5-5/ · https://about.suno.com/blog/stem-separation-updates · https://mvsep.com/algorithms · https://dynamoi.com/learn/ai-music-distribution/how-to-master-ai-music-for-streaming

## Q8. 좋은 곡 자동 선별
1. **하드 필터(탈락)**: 클리핑 샘플 다수, 앞뒤 무음 과다, 길이 이상, 위상 상관 음수(모노 상쇄), 갑작스런 음량 붕괴 구간.
2. **소프트 점수(순위 참고)**: Meta Audiobox Aesthetics(PQ·PC·CE·CU, 10초 단위 평균) — Cyanite 독립 리뷰(경쟁사, 2026-05)는 점수가 7~8에 몰리고 편향이 있다고 보고 ❓. SongEval(5차원, 라이선스 표기 상충 CC BY-NC-SA vs Apache) ❓.
3. **사람 청취**: 상위 N곡을 마스터링 전/후 음량 맞춘 A/B로 듣고 고름. 고른 결과를 기록해 점수와 비교, 가중치 보정.
- 출처: https://arxiv.org/abs/2502.05139 · https://cyanite.ai/blog/meta-audiobox-aesthetics-review/ · https://arxiv.org/abs/2505.10793 · https://github.com/ASLP-lab/SongEval

## Q9. 흔한 실수
- AI 곡을 더 세게 리미팅 → 부서짐. 거친 고역 부스트. 리미터 뒤에 EQ.
- 디더를 여러 번, 또는 24bit 납품에 디더.
- AAC/MP3로 인코딩한 뒤 피크 초과 → 파이프라인에서 **AAC 인코딩 후 True Peak 재검사**.
- 48kHz 그대로 납품(일부 유통사 오류).

## 제안 파이프라인 (승인 시 구현)
```
[수집] Suno 유료 WAV → inbox/
[분석] analyze.py: sr·LUFS·TP·LRA·컷오프·클리핑·무음·위상 (+선택 Audiobox 점수) → report.csv
[선별] 하드필터 탈락 → 상위 N곡 텔레그램으로 "들어보고 고르기" 목록
[마스터] HPF 25Hz → 고역 정리(하이셸프/디에서) → 저역 모노 → (선택) Matchering 레퍼런스 매칭
        → 가벼운 글루 컴프 → 4x 오버샘플 True Peak 리미터 → 44.1kHz 리샘플 → 16bit TPDF 디더
[검증] LUFS ±1, TP ≤ -1(크면 -2), AAC 인코딩 후 TP 재측정, 실패 시 게인 낮춰 재처리
[산출] masters/<앨범>/NN_곡.wav + 전/후 비교 mp3(음량 맞춤) + 측정표 → 텔레그램
실행: 맥미니(pedalboard 가능, 24시간) 우선 / 미니PC는 Docker(무거운 산출물은 외장 /mnt/external)
```
