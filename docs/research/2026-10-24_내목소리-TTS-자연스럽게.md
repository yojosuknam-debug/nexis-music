## Chatterbox 개선 설정

- **의미 문단 생성**: 1~3문장을 한 호출로(한글 음절 35~70개, 공백 포함 60~120자, 생성 8~16초 목표). 합치지 않을 경계: 성경 인용 시작·끝, 질문 뒤 답변, 주제 전환, 기도 시작. '아멘.'처럼 강조 기능의 짧은 문장은 독립 유지.
- 문단 사이 무음: 실제 끝단 무음을 측정한 뒤 부족분만 추가(고정 무음 중복 금지).
- 생성 음성을 다음 참조로 쓰지 않음, 원본 참조 고정.
- 탐색값(공식 최적값 아님): exaggeration 0.20(0.15/0.25/0.35), cfg_weight 0.35(0.25/0.35/0.45), temperature 0.75(0.65/0.75/0.85), min_p 0.05(0.03/0.05/0.10), atempo는 평가 땐 1.00 → 채택 후 0.96/0.92 비교, 시드 기록.
- 시험 순서: 기준선 저장 → 청크만 변경 → 참조만 변경 → exaggeration·cfg → 샘플링·감속.
- 긴 문장 가속: 원인 단정 불가(max_new_tokens=1000 존재). 앞·중·뒤 음절 속도 측정, 급가속 청크만 재생성/분할.
- punc_norm 은 ':'·';'·'…'을 쉼표 계열로 바꾸므로 성경 '3:16' 등은 앞단에서 해석.

## 문장 분할과 쉼

- '마침표 700·물음표 1,100·쉼표 450ms'가 표준이라는 근거 없음. 경계 기능·문장 길이·강조·실제 생성 무음을 함께 볼 것.
- 총 쉼 시험값(엔진 무음 포함): 가벼운 쉼표 100~220(160) / 절 경계 180~350(260) / 같은 문단 평서문 사이 300~550(420) / 질문 후 바로 설명 350~650(500) / 생각을 요청하는 질문 650~1,000(800) / 문단·주제 전환 650~1,100(850) / 성경 인용 뒤 묵상 전환 800~1,400(1,000) ms.
- 추가 무음 = max(0, 목표 총 쉼 − 앞 청크 끝 무음 − 뒤 청크 앞 무음). 여백은 앞 30~60ms, 뒤 60~120ms 남김.
- 변동 쉼은 무작위보다 문맥화가 먼저, 마지막에 ±10% 이내.
- 속도 시험 범위: 예배 3.8~4.5 음절/초, 심방 4.2~4.8 음절/초(쉼 포함), 인용·기도는 더 느리게.
- 근거: 「휴지 단위와 호흡 단위의 실현 양상 연구」(2020, 낭독 호흡 단위 약 17음절·3.4초), 낭독·자유 발화 비교(2022), 「발음속도에 따른 한국어의 휴지기 규칙」(1994), Empirical evidence for prosodic phrasing(2007).

## MPS 메모리 진단

- 14~33GB가 어떤 지표인지 먼저 구분(활성 텐서 / 드라이버 / RSS). 원인 확정 자료 없음.
- 패턴: inference_mode, 출력을 즉시 CPU로(detach().to('cpu')), del + gc.collect(), synchronize + empty_cache, torch.mps.current_allocated_memory / driver_allocated_memory 기록.

(이하 원문이 한도 초과로 일본어 출력 — 그대로 보존)

**運用上の提案**
- モデルはワーカー内で一度だけロード / 参照条件も一度だけ作成 / 生成は同時実行せず直列
- MPS出力をリストに蓄積せず、CPUへ移してファイル保存 / 長い完成音声はCPU側で連結
- ASRはTTS処理後、または別の寿命管理されたプロセスで実行
- メモリが回復しなければワーカーを終了し、親プロセスから再起動 / 再起動はまず10チャンクごとなど保守的な条件で試し、測定結果から延長
- PYTORCH_ENABLE_MPS_FALLBACK=1 はメモリリーク修正スイッチではない / watermark 変数は数値設定保留 / 上限解除は不採用 / torch.compile は診断初期は無効 / 全モデルFP16化は一括適用しない / torch 更新は別仮想環境で比較 / 「最新版で修正済み」は断定不可
- 最小の切り分け実験: A 同一テキスト30回 / B 短・中・長を交互に30回 / C Bを10回ごとの別ワーカー / D BをASRなしで。記録: チャンク番号・入力長・生成秒数・処理秒数・各メモリ指標・RSS・設定・モデルrevision
- 結論: 原因未確定でも **短命ワーカー＋チェックポイント保存＋途中再開** を先に実装する価値あり
