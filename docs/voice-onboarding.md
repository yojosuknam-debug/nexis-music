## 2. 참조 후보 3개 만들기 (맥미니)

Chatterbox 는 참조 녹음 중 **앞 6초(음색)·10초(말투)** 만 쓴다. 긴 녹음에서 **말실수·기침·숨소리 없는 8~12초 구간 3개**를 고른다.

```bash
# 맥미니: 녹음을 ~/Work/nexis-worship/ref/<이름>/ 에 두고
cd ~/Work/nexis-worship/ref
ffmpeg -i <이름>/원본.m4a -ar 24000 -ac 1 <이름>/full.wav
# 들어 보고 좋은 구간 시작 초(예: 12.0 / 41.5 / 78.0)를 골라 10초씩 자른다
for s in 12.0 41.5 78.0; do ffmpeg -y -ss $s -t 10 -i <이름>/full.wav <이름>_ko_$s.wav; done
```

- 고를 때: 목소리 크기·빠르기가 고르고, 문장이 중간에 끊기지 않는 곳.
- 영어 예배도 쓸 거면 영어 대본을 따로 녹음한다(한국어 녹음으로 영어를 만들면 한국어 억양이 섞인다).

## 3. 시험 낭독 (후보마다 1분 안팎)

참조 파일은 **환경변수로만 바꿔 끼운다**(코드 수정 없음).

```bash
B=~/Work/nexis-worship
export PATH=/opt/homebrew/bin:$PATH WORSHIP_OUT=$B/output WORSHIP_REF_DIR=$B/ref WORSHIP_DEVICE=mps \
       WORSHIP_THREADS=8 HF_HOME=$B/hf PYTORCH_ENABLE_MPS_FALLBACK=1
for f in <이름>_ko_12.0.wav <이름>_ko_41.5.wav <이름>_ko_78.0.wav; do
  WORSHIP_REF_KO=$f $B/.venv/bin/python ~/Work/nexis-music/scripts/worship/voice_cmp.py $B/output/cmp/<이름>_${f%.wav}.mp3
done
```

`scripts/worship/voice_cmp.py` 는 최근 심방 말씀 앞부분(없으면 기본 대본, 질문 포함 약 1분)을 같은 규칙으로 읽는다. 대본 파일을 두 번째 인자로 줄 수도 있다. 후보만 바꾸고 다른 설정은 그대로 두어야 비교가 된다.

## 4. 검수

**자동 지표(로그에 나옴)**

| 지표 | 기준 | 처리 |
|---|---|---|
| 되읽기 오류(Whisper) | ≤12% 통과 / 넘으면 자동 재생성(최대 3번) | 같은 곳이 계속 틀리면 **발음 사전**(`SPEAK_KO`)·숫자 규칙을 고친다 — 다시 만들기만 반복하지 않는다 |
| 중요한 말 | 성경 책·장절·이름·숫자·'아니다' 같은 부정어는 오류율과 상관없이 귀로 확인 | |
| GPU 메모리 | `GPU …GB` — 9GB 넘으면 저장한 문장부터 자동으로 다시 띄워 이어 만든다 | 계속 넘으면 `WORSHIP_MPS_LIMIT_GB` 를 낮춘다 |
| 길이 | 1분 대본이 50~80초 | 너무 짧으면 빠뜨린 말, 너무 길면 이상한 쉼 |

**귀로 듣기(본인·가족이 이름 모르고)** — ①본인 같은가 ②듣기 편한가 ③8분 들어도 덜 피곤한가를 따로 점수 매긴다.

## 5. 정식 적용

1. 고른 후보를 `ref/<이름>_ko.wav` 로 이름 정해 **세 기기 ref 폴더**에 넣는다(맥미니 `~/Work/nexis-worship/ref`, 미니PC `/mnt/external/nexis-worship/ref`, PC `D:\YH\voice-lab\ref`).
2. 계속 쓸 거면 `build_worship.py` 의 `REF` 기본값을 바꾸고 커밋, 한 번만이면 `WORSHIP_REF_KO=<파일>` 로 실행.
3. **심방 말씀 8분**(`simbang.py`)을 처음부터 끝까지 만들어 통으로 듣는다 → 문제없으면 **예배 17분**(`worship-mac.sh`).
4. 결과·설정·참조 파일 이름을 `ref/<이름>/동의.md` 아래에 기록.

## 6. 지금 규칙(바꾸지 말고 그대로 쓰는 것)

| 규칙 | 값 | 이유 |
|---|---|---|
| 생성 단위 | 한 문장씩(12자 미만은 다음 문장과, 60자 넘으면 쉼표·절 끝에서 나눔) | 묶으면 쉼 없이 빨라짐(10-23), 길면 갑자기 빨라짐(10-24) |
| 쉼(총, 무음 다듬은 뒤) | 마침표 0.8 · 쉼표 0.3 · 생각을 청하는 질문 1.0 · 바로 답이 이어지는 질문 0.6초 | B 확정(10-24) + 조사 |
| 생성 설정 | exaggeration 0.20 · cfg 0.35 · temperature 0.75 · repetition_penalty 1.2 · min_p 0.05 (`WORSHIP_TUNE`, 기본 켬) | '구연동화 같다'(10-22) → 10-24 비교 샘플 ③ 확정 |
| 속도 | 완성 후 8% 느리게(atempo 0.92) | '약간만 느리게'(10-23) |
| 발음 | `SPEAK_KO`(말씀Log→말씀로그, AI→에이아이 …) + 숫자 읽기(`normalize_ko`) — **낭독에만**, 자막은 원래 글 | 10-24 |
| 자막 | 장·절은 숫자(`민수기 6장 24절`) | 10-24 |
| 원고 | 한 문장 40자 안팎, 60자 이내 | 긴 문장 가속 방지 |

## 7. 흔한 실패와 처음 해 볼 것

| 증상 | 처음 해 볼 것 |
|---|---|
| 문장마다 새로 읽기 시작하는 느낌 | 참조를 '설명하듯 이어 읽는' 구간으로 바꿔 보기, 의미 묶음(`WORSHIP_CHUNK=para`) 비교 |
| 뒤로 갈수록 빨라짐 | 그 문장을 더 짧게 — 원고 단계에서 고치는 게 가장 확실 |
| 고음이 따갑다·'칙' | **보정 안 한 원본 참조**로 되돌리기 |
| 특정 단어를 계속 틀림 | `SPEAK_KO` 에 그 단어 발음 추가(전체 발음 변환은 하지 않는다) |
| 중간에 말투·목소리가 바뀜 | 참조는 처음 고른 원본 하나로 고정(만든 소리를 다시 참조로 쓰지 않는다) |
| 만들다 멈춤·아주 느림 | 맥미니 메모리 확인 — 시뮬레이터·로컬 AI 같은 무거운 작업과 겹치지 않게. 다시 실행하면 저장된 문장(`_chunks`)부터 이어 만든다 |

## 7-1. 알아낸 것 (10-24 맥미니 실측)

- **GPU 메모리는 한 번에 읽히는 글 길이에 따라 커진다.** 한 문장씩(60자 이내) ≈ 4~5GB, 1~3문장 묶음(≈100자) ≈ 16GB. 긴 문장을 나누는 규칙이 속도뿐 아니라 메모리도 지킨다.
- 9GB 를 넘으면 자동으로 다시 띄워 저장한 문장부터 이어 만든다(시험: 4GB 한도에서 2번 다시 띄우고 정상 완성).
- 되읽기 검사는 Whisper 결과도 같은 숫자 규칙으로 맞춰 비교한다(전엔 '6장'을 오류로 봐 28% → 이제 0%).
